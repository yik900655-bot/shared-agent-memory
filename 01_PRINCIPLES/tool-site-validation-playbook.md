# 工具站立项与交付验证方法

依据 2026-11-11 和 2026-11-12 用户确认的复盘整理。项目之间复用验证方法。模板数量、模型、API、文生图或图生图、图片增强和页面数量由各项目决定。[两轮工具站调研复盘](../05_WIKI/two-round-tool-site-research-retrospective.md)

## 四个根本问题

- **验收层级混乱。** 构建、API 或模拟测试只能证明技术环节，交付还需要质量与任务证据。
- **把流量当需求。** 搜索量描述查询规模。用 SERP 和真实任务核实用户是否需要页面提供的结果。
- **只看门槛不看对手。** 看专门页面与排名位置、流量归属、交付能力及对手的投入动机。KD 和 DR 是辅助指标。
- **用调研逃避决策。** 先写可推翻条件和时间预算。证据足以排除关键淘汰理由时，就决定做小验证、暂缓或淘汰。

## 四道立项门

| 立项门 | 判断依据 | 调整或暂停的信号 |
| --- | --- | --- |
| 1. 获客路径 | 写明首批用户、渠道或查询、承接页和可观察指标。 | 找不到可触达的入口，或渠道的投入超过项目边界。 |
| 2. 搜索意图与需求 | 结合目标地区 SERP、词族和任务证据，写出用户要得到的结果。 | 查询主要是导航、教程或其他任务，拟做工具承接不了。 |
| 3. 竞争盘面 | 比对目标排名位置、专门页面、页面流量及对手投入理由。口径、数据缺失和动机推断分别标注。 | 可触达的结果位没有可行切口，或核心任务的交付成本明显超出预算。 |
| 4. 技术交付与商业路径 | 用自身技术栈低成本预检真实交付，记录使用限制、成本、商业路径或练习目标。 | 核心结果无法在预算内交付，或平台限制使目标场景无法成立。 |

工具页按能否完成任务、输出能否使用、复制或导出评估。内容站按答案覆盖、来源质量、时效与维护成本评估。混合 SERP 中分别判断工具和内容页面承接的意图。

## 交付验证三层

1. **成功定义。** 开发前写明用户是谁、在哪使用、要得到什么、怎样算成功。先定义最低可用质量。
2. **交付路径。** 用相同或可比输入，以普通用户身份从进入、输入、选择、配置、执行，走到结果、修改及下载、导出或复制。记录「它让我填什么」「我在哪一步等待」「我在哪一步感到惊喜」「我在哪一步差点放弃」。同时记录价格、付费节点、核心卖点和可追溯的用户抱怨，写明受阻步骤。
3. **结果验收。** 用有权使用的真实输入完成任务，人工打开交付物，在目标场景核对，并与竞品同类结果对照。上线前走查完整流程。分别填写下表。

| 验收 | 通过证据 |
| --- | --- |
| 技术 | 构建、请求、转换和复制等关键步骤能运行，记录环境和测试方式。 |
| 质量 | 代表样本达到最低可用标准，保留样本、人工判断和同任务对照。 |
| 任务 | 用户在目标场景取得并能使用结果，记录实际粘贴、保存、导出或其他消费结果的证据。 |

## 九步执行

| 步骤 | 完成标准 |
| --- | --- |
| 1. 假设与反证 | 一句话定义用户任务、交付物和可推翻条件，写下本轮时间与费用边界。 |
| 2. 获客路径 | 确认首个渠道、目标人群、承接页和验证信号。 |
| 3. 关键词意图 | 核对地区、语言、查询和实际用户任务。搜索量按来源与日期记录。 |
| 4. SERP | 看专门页面、排名位置、流量口径和对手动机，写出可争切口及反证。 |
| 5. 词族 | 按相同任务归并查询，记录用同页承接与另开页面的依据。 |
| 6. 竞品体验 | 用可比输入走核心流程、付费节点和实际交付，留样本及证据。 |
| 7. 技术商业预检 | 自身技术栈走一个代表性任务，分别记录三类验收证据、成本、能力边界和商业路径。 |
| 8. MVP 决策 | 做、暂缓或淘汰。若进入 0→1 小验证，优先单页、一个任务、明确暂缓项和停止条件。 |
| 9. 上线复盘 | 上线前人工走查，上线后核对搜索、使用及下载、复制或导出数据，决定继续、调整或暂停。 |

搜索量 100、KD 40、三个可赢词、五个扩展页面等历史数字只作参考。记录口径和适用场景，再结合四道立项门判断。证据够用时从调研进入有边界的小验证，保留剩余未知。

记录时分列已核实事实、Agent 转述、推断与未知。未经独立核验的群聊、文章摘要标为转述。实际记录用 [调研模板](../templates/research-template.md)。
