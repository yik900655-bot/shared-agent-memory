# Dreaming 手动整理流程

项目阶段结束、积累了一批 INBOX 条目或用户要求复盘时，由具备相应权限的工具或人员手动执行。流程参考 [Cognition Agent Memory Repo](https://cognition.com/agent-memory-repo)。

1. **阅读 INBOX。** 拉取最新版本，打开 [INBOX](../06_INBOX/README.md)，选出本轮范围，核对项目、日期、来源和验证状态。
2. **检查重复。** 找到已记录同一发现的条目，保留一条主记录和有效证据，给重复条目标明去向。
3. **检查冲突。** 对照两边的来源、日期、环境和口径。无法解决时记录冲突和下一项验证，保留各方证据。
4. **核实来源。** 优先查原始资料、实际运行结果或用户确认。记录核实日期、证据和能复现的步骤。
5. **标明证据强度。** 将观察到的事实、基于证据的推断和待验证问题分别记清。无法复核的条目保持待验证。
6. **提取长期经验。** 写清可复用做法、适用条件、复现步骤和成功标准。只有证据充分且可复查的做法进入 Wiki。
7. **更新当前状态。** 用最新证据更新 [CURRENT_STATE](../02_CURRENT_STATE/current-project.md) 和相关项目进度。给出待解决项和下一步。
8. **检查决策。** 按 [决策规则](../04_DECISIONS/README.md) 记录已经确认的新决策。涉及调整用户已确认的原则或决策时，先提交证据与待确认提案，获得用户明确确认后再变更。
9. **沉淀到 Wiki。** 用 [经验模板](../templates/experience-template.md) 新建或更新条目，在 [Wiki 索引](README.md) 加入链接，并给已整理的 INBOX 条目标注去向。
10. **保留记录并推送。** 复核链接、敏感信息与 Git 差异。将本轮整理内容提交并推送，保留 INBOX 原始线索、历史决策及 Git 历史。

完成标准为本轮处理的条目都有明确状态与去向，未解决的分歧有下一项核验动作，新增 Wiki 条目可以追溯到原始证据。推送后用 `git status --short --branch` 核对工作区干净且分支已同步。
