# 两轮工具站调研复盘

整理于 2026-11-12。第一轮来自 [Roblox Game Icon Generator 复盘](../03_PROJECTS/roblox-game-icon-generator/retrospective.md)，重点是把技术接通和真实用户交付分开。第二轮来自用户确认的工具站调研复盘摘要，重点是可推翻条件、获客入口、搜索意图、竞争盘面和投入边界。合并后的执行标准见 [工具站立项与交付验证方法](../01_PRINCIPLES/tool-site-validation-playbook.md)。

## 来源与证据

- **已核实事实。** Icon Generator 的本地原型、KIE API 接入与模拟测试有归档。真实生成与成品质量未完成验收。Font Generator 的 Roblox 字段规则以官方支持文档为依据。[KIE 接入报告](../03_PROJECTS/roblox-game-icon-generator/kie-api-integration-report.md) · [Roblox 显示名称说明](https://en.help.roblox.com/hc/en-us/articles/4401938870292-Changing-Your-Display-Name)
- **Agent 转述。** 哥飞 Agent 对群聊或文章的总结、关键词数据和趋势判断按转述归档。原始群聊、文章和数据面板未经独立核验时，禁止写成已核实的哥飞原话。本页的归纳是方法整理，未补造原文引语或数据截图。
- **推断。** 对手为什么投资源、哪个页面可能赢、纯前端方案的交付成本都需要写出依据和反证。
- **未知。** 实际排名与流量归属、用户在哪个 Roblox 字段使用样式、竞品转换后能否真实粘贴保存，留待实测。

## 四个根本问题

| 问题 | 两轮复盘中的表现 |
| --- | --- |
| 验收层级混乱 | Icon 项目有模拟结果和可下载 PNG，缺少真实任务、质量和使用证据。Font 项目即使转换和复制通过，也要在实际目标字段验收。 |
| 把流量当需求 | 搜索量可能同时覆盖找工具、找教程、查兼容性和其他任务。需要核对用户期待的最终结果及获得首批用户的路径。 |
| 只看门槛不看对手 | 搜索量、KD、DR 只能初筛。须看首页结果是否由专门页面占据、哪些位置可争、流量归属哪页及对手为何投入。 |
| 用调研逃避决策 | 先设可推翻条件、投入上限和停止点。调研到足以判断不淘汰即可做小验证，剩余未知纳入上线后观察。 |

## 五个核心方法的修正

| 方法 | 修正后的动作 |
| --- | --- |
| 立项假设 | 先写用户、任务、交付物和反证，再取证。证据触发淘汰或暂缓时记录决策。 |
| 搜索需求 | 先确认首个获客入口，再核对核心词、词族与 SERP 意图。对照实际使用结果来判断产品需求。 |
| 竞争分析 | 分析专门页面、具体排名、页面流量和对手动机。把站点总流量、估算和没有数据的情况分开记。 |
| 竞品和交付 | 同一用户任务、可比输入，走到实际可用的结果。分别记录技术、质量和任务验收，价格与付费节点纳入交付路径。 |
| 投入决策 | 0→1 优先单页、一个任务和低成本预检。由证据决定是否加差异化功能。设定时间、费用和停止点，按上线反馈复盘。 |

## 五个新增盲区

1. **首批用户入口。** 有关键词数据时仍要指明哪一页承接、能触达谁，以及如何核对收录、展示或其他渠道入口。
2. **查询与交付的错配。** 相同的词可能指向不同场景。工具页验证操作与结果，内容站验证答案覆盖、来源与更新成本。
3. **对手投入的动机。** 专门页面可能是主产品、工具集的一页或导流入口。页面规模、排名和流量是观察，投入意图需单列为推断。
4. **结果离开工具后的表现。** 复制、下载和导出只是链路的一部分。还需确认目标平台是否接受，显示是否正常，结果是否达到人工质量标准。
5. **商业与研究的停止条件。** 在开发前约定一次低成本实验可承担的费用和工时。用实测淘汰条件与上线数据判断是否继续，避免为了凑阈值和扩展页增加范围。

## 数字标准审查

| 旧参考 | 当前用法 |
| --- | --- |
| 搜索量 100 | 只作规模参考，记录地区、月份、数据工具和匹配口径。 |
| KD 40 | 只在同一来源和口径内辅助比较，结合实际 SERP 与交付能力。 |
| 三个可赢词 | 用于检视可能的查询入口，一个有证据的切口也可进入限时小验证。 |
| 五个扩展页面 | 用于讨论扩展空间，是否建页由独立用户任务和维护成本决定。 |

上述数字均无通用淘汰效力。项目自己的时间、费用和停止点按其决策执行。

## 九步调研流程

1. **假设与反证**记录任务、初始判断及可推翻条件。
2. **获客路径**确定首个渠道、承接页和验证指标。
3. **关键词意图**核对目标人群和结果需求。
4. **SERP**拆专门页面、实际位置、页面流量和对手动机。
5. **词族**按用户任务聚合同义与相邻查询。
6. **竞品体验**走核心流程和付费节点，保存可比输出。
7. **技术商业预检**核查三类验收、成本与商业路径。
8. **MVP 决策**决定做小验证、暂缓或淘汰，固定范围和停止条件。
9. **上线复盘**先人工走查，再根据搜索、使用与导出、下载或复制证据决定下一步。

## Roblox Font Generator 案例

按四道门看，这个项目目前有英文搜索入口假设、核心词与专门工具页线索。美国月搜索量 1600、哥飞版 KD 36.6、趋势相对平稳来自用户转交的哥飞 Agent 报告。实际 SERP、流量归属和搜索意图仍待验证。技术初判为 A 类纯前端 Unicode 映射，约一天的 MVP 是工作量估计。

先给三款竞品同一文字，核对生成、复制及真实 Roblox 目标字段。技术验收看转换和复制，质量验收看样式可读且保留输入含义，任务验收看目标字段实际接受及显示。若最初锁定的字段无法达到最低可用质量，先用证据重审任务范围。竞品页面的兼容宣传属于产品方陈述。

用户确认将其作为低成本练习。45～60 分钟预检通过后约一天做单页 MVP，上线约 30 天后看收录、自然搜索、使用与复制数据，再决定继续或暂停。[项目调研](../03_PROJECTS/roblox-font-generator/research.md) · [练习项目决策](../04_DECISIONS/2026-11-12-roblox-font-generator-practice-mvp.md)
