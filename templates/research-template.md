# 调研或新发现标题

- 来源（填写可核实的链接、记录或用户确认）
- 日期（YYYY-MM-DD）
- 所属项目（填写项目名或“跨项目”）
- 信息类型（已核实事实、Agent 转述、推断或未知）
- 验证状态（待验证、已核实、有冲突或已证伪）

## 问题和观察

写明要回答的问题、观察环境和证据。事实附来源和复查方式。

## 假设、反证与证据口径

- 初始假设（填写用户、任务、交付物与首个获客入口）。
- 可推翻条件（先写调整、暂缓或淘汰的触发条件）。
- 事实（附原始证据、日期、地区、设备与测量口径）。
- Agent 转述（附转述来源和可追溯的原文，注明原始证据是否核验）。
- 推断（列依据与可能的反证）。
- 未知（写缺口、补证动作及其是否影响当前决定）。

## 工具站检查清单

适用时逐项勾选并填写证据、结论或待补动作。完整方法见 [工具站立项与交付验证方法](../01_PRINCIPLES/tool-site-validation-playbook.md)。

- [ ] 已区分工具页与内容站，写明首批用户的获客入口和承接页。
- [ ] 已核对核心词与词族的意图，区分搜索数据与产品需求证据。
- [ ] 已检查目标 SERP 的专门页面、位置、流量口径和对手投入动机，标明推断。
- [ ] 已定义用户、使用场景和最终交付结果（填写一句话需求与交付物）。
- [ ] 已亲自以普通用户身份完成竞品核心流程（填写输入、等待、惊喜、差点放弃的步骤及实际导出结果）。
- [ ] 已检查价格页和付费节点（填写核心卖点、付费理由、价格日期和用户反馈）。
- [ ] 已用自己的技术栈进行低成本能力预检（填写版本、真实输入、输出样本、耗时和成本）。
- [ ] 已分别写技术、质量、任务验收标准（填最低可用质量、可比样本和目标场景验证）。
- [ ] 已写明商业路径或练习目标、单页 MVP 范围、暂缓项和四道立项门的判断。
- [ ] 已设定开发时间、费用上限与停止条件（填写上限、复核日期和超限处理）。
- [ ] 已安排上线前人工走查（填写验收人、代表任务和预期交付物）。

上线后补记实际搜索展示、点击、使用、导出或下载等数据的统计口径与观察周期。用证据决定继续、调整或暂停。

## 下一步与整理去向

记录结论为进入小验证、暂缓或淘汰，说明反证与通过标准。量化指标须附口径与适用条件。整理后补充日期、结论及目标文件链接。
